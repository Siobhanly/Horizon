## [已停止维护的 Fastjson 1.x 曝出高危 RCE 漏洞](https://t.me/zaihuapd/42797) ⭐️ 9.0/10

安全研究员 Kirill Firsov 披露了 Fastjson 1.2.68 至 1.2.83 版本中存在一个高危远程代码执行（RCE）漏洞。该漏洞利用无需开启 autoTypeSupport 或依赖 classpath gadget，可在 JDK 8、17 和 21 等多个版本上被利用。 此事至关重要，因为 Fastjson 1.x 已停止维护且不会收到安全补丁，导致所有使用这些版本的应用将永久暴露于风险之中。唯一的补救措施是紧急升级到 Fastjson2，这影响了大量依赖此广泛使用库的 Java 应用。 该漏洞（尚未分配 CVE 编号）的显著特点是不需要开启 autoTypeSupport，从而绕过了常见的缓解措施。Fastjson 1.x 已于 2024 年 10 月正式停止维护，确认官方将不会发布修复补丁。

telegram · zaihuapd · Jul 27, 10:31

**推荐使用场景**:
['一名维护使用 Fastjson 1.2.76 进行 JSON 解析的旧版 Spring Boot 应用的 Java 开发者，应立即计划迁移到 Fastjson2，以防止潜在的服务器被控制。', '安全工程师可以利用此披露信息，扫描其组织的代码库和容器镜像中是否存在易受攻击的 Fastjson 1.x 版本，并优先进行修复。', 'DevOps 团队可以更新部署流水线，阻止包含 Fastjson 1.x 依赖的构建，将升级到 Fastjson2 作为一项合规性要求强制执行。']

**背景**: Fastjson 是阿里巴巴开发的一个流行的高性能 Java JSON 解析和生成库。远程代码执行（RCE）是一种严重的安全漏洞类型，允许攻击者在目标服务器上运行任意命令。该库历史上曾多次出现严重的反序列化漏洞，通常通过禁用 'autoTypeSupport' 等功能或依赖特定类路径组件来缓解。

**标签**: `#security`, `#vulnerability`, `#RCE`, `#Java`, `#Fastjson`

## [vLLM v0.26.0 发布：大幅提升 DeepSeek-V4 性能并引入 Inkling 模型家族](https://github.com/vllm-project/vllm/releases/tag/v0.26.0) ⭐️ 8.0/10

vLLM v0.26.0 版本正式发布，引入了全新的 Inkling 模型家族，在多个硬件平台上显著提升了 DeepSeek-V4 的端到端性能，并新增了 fp32 lm_head 支持和灵活的注意力后端等特性。 作为广泛使用的大模型推理引擎，这些性能优化直接意味着在部署 DeepSeek-V4 等大型模型时能获得更低的延迟、更高的吞吐量和更低的运营成本，而新增的模型支持则为开发者扩展了生态。 DeepSeek-V4 的性能提升包括一个专用的路由内核使 TPOT 提升 2.94%，以及一个速度提升 1.5 到 2 倍的 fused_topk_bias 内核。此版本还完善了带分层二级存储的 KV 缓存卸载功能，并增加了一个基于 Rust 的基准测试工具。

github · khluu · Jul 27, 01:06

**推荐使用场景**:
['云服务提供商可以利用新的优化在 AMD 或 Intel 硬件上部署 DeepSeek-V4，为其 API 服务实现更优的成本效益比。', '研究团队可以利用新的 Inkling 模型家族及其完整的支持栈（LoRA、推测解码、量化），高效地微调和部署自定义模型。', '基础设施工程师可以使用灵活的注意力后端选择功能，为结合了滑动窗口和全注意力等不同机制的混合模型进行优化。']

**背景**: vLLM 是一个面向大语言模型 (LLM) 的高吞吐量、高内存效率的推理引擎。DeepSeek-V4 是一个大规模的混合专家 (MoE) 模型，由于其规模和架构，优化其推理过程颇具挑战。Inkling 模型家族是 vLLM 最新原生支持的一组新模型。
